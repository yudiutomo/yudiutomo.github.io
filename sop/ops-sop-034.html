SOP - REKONSILIASI EVENT ALAT & DOWNTIME

Nomor Dokumen

OPS-SOP-034

Kategori

Referensi operasional

Pemilik Proses

Operasi Tambang

Penggunaan

Review evidence dan keputusan

1. Tujuan

Menetapkan cara merekonsiliasi equipment event, durasi downtime, catatan supervisor, dan technical finding sebelum informasi tersebut digunakan untuk analisis performa operasional atau management reporting.

2. Ruang Lingkup

Berlaku untuk mobile equipment yang material terhadap produksi serta event operasional pendukung yang tercatat pada system event log, shift handover, maintenance record, dan production summary.

3. Penggunaan Source Berdasarkan Tujuan

Source

Penggunaan utama

Control

System / fleet event log

Recorded event start/end time, status, lokasi, asset.

Gunakan system timestamp sebagai referensi event timing bila tersedia.

Shift handover

Konteks operasional, observasi, pertanyaan terbuka.

Durasi naratif dapat bersifat perkiraan dan tidak boleh diam-diam menggantikan system time.

Maintenance record

Technical inspection atau maintenance finding.

Technical finding tidak otomatis membuktikan production impact.

Production record

Plan, actual, variance, hourly performance.

Performance gap tidak otomatis membuktikan event penyebab loss.

4. Status Event

Status

Makna

OPEN

Event atau discrepancy masih memerlukan verification.

RECONCILED

Source terkait sudah dibandingkan dan resolving source sudah didokumentasikan.

CLOSED

Event record lengkap dan tidak ada material reconciliation item yang tersisa.

5. Prosedur Rekonsiliasi

  1. Identifikasi seluruh record yang merujuk asset, lokasi, dan operating period yang sama.
  2. Bandingkan start time, end time, duration, status, dan narrative description.
  3. Bila nilai/istilah berbeda, pertahankan kedua nilai dan sumber; uji dahulu apakah metrik, unit, start/end, cakupan, dan definisinya sebanding. Jangan memberi label CONFLICT sebelum kesetaraan metrik terverifikasi.
  4. Gunakan system/event log sebagai referensi timestamp bila tersedia, sambil mempertahankan konteks supervisor secara terpisah.
  5. Gunakan maintenance record untuk technical condition, bukan untuk menginfer production impact kecuali memang dikuantifikasi.
  6. Bila discrepancy atau CONFLICT belum teratasi, pertahankan OPEN dan nyatakan definisi serta evidence yang diperlukan; jangan memaksakan rekonsiliasi.
  7. Dokumentasikan resolving source sebelum status diubah menjadi RECONCILED atau CLOSED.

6. Causality Guardrail

Equipment event yang terjadi pada periode production shortfall belum cukup untuk membuktikan bahwa event tersebut menyebabkan shortfall. Causal statement memerlukan evidence yang menghubungkan event dengan measurable operational impact serta mempertimbangkan constraint material lainnya.

7. Contoh Logic Rekonsiliasi

Observasi

Perlakuan yang diperlukan

Event log berisi durasi STANDBY; handover berisi estimasi UNAVAILABLE.

Catat DISCREPANCY / NEEDS VERIFICATION. Verifikasi apakah definisi, titik awal/akhir, dan periode metrik setara. Hanya beri status CONFLICT jika kesetaraan terbukti dan nilainya berbeda.

Equipment standby terjadi pada jam dengan output terendah.

Catat temporal association. Jangan menyebut root cause tanpa impact evidence.

Maintenance mengonfirmasi masalah teknis.

Catat technical finding sebagai SUPPORTED. Production impact tetap dinilai terpisah kecuali dikuantifikasi.

Tidak ada record yang membuktikan penyebab production gap.

Catat UNKNOWN dan jelaskan evidence tambahan yang diperlukan.

8. Persyaratan Close-out

  • Event timing dan duration yang sudah direkonsiliasi terdokumentasi.
  • Source yang menyelesaikan discrepancy teridentifikasi.
  • Technical finding dan production impact tidak dicampur.
  • Uncertainty yang tersisa dinyatakan eksplisit.
  • Isu material yang belum selesai dieskalasikan sesuai standar operational exception.

9. Aturan penentuan status evidence

Bukti

Perlakuan

Durasi STANDBY pada event log

SUPPORTED sebagai pernyataan dari log, jika source tersedia

Estimasi UNAVAILABLE pada handover

SUPPORTED sebagai isi catatan naratif, jika source tersedia

Hubungan dua definisi

NEEDS VERIFICATION sebelum CONFLICT; definisi dan interval harus dibandingkan

Root cause suatu event

UNKNOWN bila belum ada evaluasi dampak dan kontribusi terukur
